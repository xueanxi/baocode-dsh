## 实现要求

### 1. 定位（`dsh_locate`）

```dart
class DshInstall {
  final String node;      // 跑 bin.js 的 node 可执行文件
  final String binJs;     // <dsh>/lib/bin.js
  final String version;   // 读 <dsh>/package.json 的 version，读不到就 'unknown'
  final String packageDir;
}

Future<DshInstall?> locateDsh({String? setting, Map<String,String>? environment});
```

顺序与规则：

1. 设置值非空：接受两种写法——单个路径（视为 `bin.js`，用 `Platform.resolvedExecutable` 之外的 `node`？不：用 PATH 里的 `node`，找不到再报 null）或 `node|bin.js` 两段（`|` 分隔，两侧去空白）。
2. PATH 上的 `dsh` / `dsh.cmd` / `dsh.ps1`：读垫片文本，从中解析出 `.../@deepseek-ai/dsh/lib/bin.js`（`.cmd` 里是 `"%dp0%\node_modules\@deepseek-ai\dsh\lib\bin.js"`）；解析不到就跳过。
3. 平台 npm 全局根（两条规则不一样，别混）：
   - POSIX：`<prefix>/lib/node_modules/@deepseek-ai/dsh/lib/bin.js`，prefix 取 PATH 里 `bin/node`（或 `bin/dsh`）的上两级，另加 `/usr/local`、`~/.npm-global`、`~/.nvm/versions/node/*`；
   - Windows：`%APPDATA%
pm
ode_modules\@deepseek-ai\dsh\libin.js`。
   定位以**登录 shell 的环境**为底（macOS 从 Finder 启动时 PATH 极简；Windows 用应用自身环境），复用 `ClaudeEnvironment.of()`，不要只读 `Platform.environment['PATH']`。
4. 版本：解析 `packageDir/package.json` 的 `version`；解析失败返回 `unknown`，**不阻断**。

`node` 的取法：设置里给了就用；否则用 PATH 里的 `node`；再退到与 dsh 同级的 `node_modules/.bin`（不强制）。

### 2. 传输（`dsh_transport`）

```dart
abstract interface class DshTransport {
  Stream<Map<String, Object?>> get messages;
  void write(Map<String, Object?> message);
  Future<void> get exited;
  void close();
  String? get executable;
}

Future<DshTransport> startDsh(DshLaunch launch);
```

- `DshLaunch`：`cwd`、`install`、`patchFile`、`permissionMode`（`read-only|workspace-write|danger-full-access`）、可选 `environment`。
- 命令行：`[install.binJs, '--profile', 'acp', '--patch', patchFile]`，可执行文件是 `install.node`；**不用 runInShell**（F20）。
- 环境：父环境 + `DSH_PERMISSION_MODE=permissionMode`；Windows 上 `includeParentEnvironment: true`。不设 `DSH_HOME`（共享，F19）。
- stdout：UTF-8（allowMalformed）+ LineSplitter + `jsonDecode`；不是 JSON 的行进 stderr 环（保留最后 30 行）。
- stderr：同样按行收进环。
- 结束：stdout 关闭且进程退出后，发一条 `{'type': 'transport_exit', 'code': n, 'stderr': ...}` 再关闭流。
- `close()`：关 stdin，让 dsh 自己 flush 并 dispose（约 5 秒；会回收工作区 ACL 授权），**等待 ≥6 秒**仍未退出才 `taskkill /pid <pid> /T /F`；其它平台先 `kill()`，再等 6 秒后 `kill(ProcessSignal.sigkill)`。立刻强杀会丢 flush 与投影缓存。
- 子进程登记：新增 `DshProcessRegistry extends ChildProcessRegistry`；识别器**解析命令行**而非子串匹配：node 可执行名 + 分辨出的绝对 `lib/bin.js` 路径 + `--profile acp` 三段都在才认。文件用 `DataDirectory.current.processRegistryFile('dsh')`。
- 测试用的 `forProcess(Process)` 工厂（`@visibleForTesting`），与 Claude 传输同构。

### 3. 补丁（`dsh_patch`）

```dart
class DshPatch {
  static String content({required String version, String? bashPath});
  static Future<String> ensure({required DshInstall install, required String directory, String? bashPath});
}
```

- 内容按规格「profile 补丁」一节，逐字生成；头部注释写 `# Generated by BaoCode for dsh <version>. Do not edit.`
- 目录 0700、文件 0600；不含 `!!js`；版本取被定位包 `package.json` 的 `version`（**不是** `initialize.agentInfo.version`，它恒为 `0.0.1`）。
- 只有 `bashPath != null`（调用方确认 acp profile 里装有 `dsh-gitbash-shell`）时，追加**两行**（缺一不可，只加执行器不会让 `bash` 工具出现）：
  ```yaml
  - id: bash-sandbox
    name: dsh-gitbash-shell/shell
    config:
      timeoutMs: 60000
      bashPath: "<bashPath>"
  - id: tool-bash
    disabled: false
  ```
  否则两行都不写。
- `ensure`：文件不存在、或头部版本与当前 dsh 版本不同 → 原子写入（临时文件 + rename）；否则复用。返回文件路径。
- 目录由调用方传（`DataDirectory.current.dshDir`），本类不碰全局。

### 4. 路径设置（`dsh_path_setting`）

照 `claude_path_setting` 的三段式：`settingKey = 'dshCode.path'`、`parse`（trim、空串→null）、`static String? Function() current`。**本票只提供类与解析，不接线**。

### 5. 数据目录

`lib/platform/data_dir.dart` 只加：

```dart
String get dshDir => p.join(path, 'dsh');
```
